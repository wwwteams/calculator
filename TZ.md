# Техническое задание

**на разработку консольной программы «Расчёт сдачи минимальным количеством монет»**

| Поле | Значение |
|---|---|
| Версия документа | 1.0 |
| Дата | 21.10.2026 |
| Исполнитель | _ФИО студента, группа_ |
| Заказчик | _ФИО преподавателя / организация_ |

## 1. Общие сведения

### 1.1 Наименование
Консольная программа «Coin Change» для расчёта сдачи с резервным копированием кассовых настроек.

### 1.2 Основание для разработки
Учебное задание: создание консольной программы на языке Python для нахождения минимального количества монет заданных номиналов, необходимых для выдачи сдачи (жадный алгоритм).

### 1.3 Термины
- **Номинал** — достоинство монеты (целое число > 0).
- **Сдача** — разница между оплаченной суммой и ценой покупки.
- **Жадный алгоритм** — алгоритм, который на каждом шаге берёт наибольший подходящий номинал.
- **Кассовые настройки** — название кассы, валюта и список доступных номиналов (`config/settings.json`).
- **Резервная копия** — файл с копией кассовых настроек, датой создания и контрольной суммой SHA-256.

## 2. Цель и назначение
Автоматизировать расчёт сдачи минимальным числом монет и обеспечить сохранность и возможность восстановления кассовых настроек.

## 3. Требования к программе

### 3.1 Функциональные требования

| № | Требование |
|---|---|
| FR-1 | Расчёт сдачи жадным алгоритмом по списку номиналов из настроек. |
| FR-2 | Ввод данных через консоль (интерактивное меню и аргументы командной строки). |
| FR-3 | Ввод данных из текстового файла (UTF-8), вывод результата в текстовый файл. |
| FR-4 | Строка входного файла содержит одно число (сумма сдачи) или два числа «оплачено цена». Пустые строки и строки, начинающиеся с `#`, игнорируются. |
| FR-5 | Просмотр и изменение списка номиналов; номиналы проверяются (целые, > 0, без повторов, список не пуст). |
| FR-6 | Создание резервной копии кассовых настроек вручную. |
| FR-7 | Восстановление настроек из выбранной или последней резервной копии с проверкой контрольной суммы. |
| FR-8 | Перед восстановлением автоматически создаётся страховочная копия текущих настроек. |
| FR-9 | Хранится не более 10 последних резервных копий, старые удаляются. |
| FR-10 | Если сумму невозможно выдать точно (остаток > 0), выводится сообщение об ошибке. |
| FR-11 | Ошибка в одной строке файла не прерывает обработку остальных; в результат записывается `ОШИБКА (строка N): …`. |

### 3.2 Нефункциональные требования

| № | Требование |
|---|---|
| NFR-1 | Python 3.8 и выше, только стандартная библиотека. |
| NFR-2 | Работа на Windows, Linux, macOS. |
| NFR-3 | Запись файлов настроек и копий выполняется атомарно (через временный файл), чтобы не получить частично записанный файл. |
| NFR-4 | Программа не завершается аварийно (traceback) при неверных данных пользователя; выводятся понятные сообщения, код возврата 1. |
| NFR-5 | Время расчёта одной суммы — менее 1 с при суммах до 10^9 и до 100 номиналов. |

### 3.3 Алгоритм расчёта
1. Номиналы сортируются по убыванию.
2. Для каждого номинала: `количество = остаток // номинал`, `остаток = остаток % номинал`.
3. Если после перебора остаток ≠ 0 — сдачу выдать нельзя.

> **Ограничение:** жадный алгоритм даёт оптимальный результат для «канонических» систем номиналов (например, 1, 2, 5, 10). Для произвольных наборов (например, 1, 3, 4 при сумме 6) результат может быть неоптимальным. Это принято как допущение задания.

### 3.4 Алгоритм резервного копирования и восстановления
**Копирование:** прочитать и проверить настройки → сформировать JSON `{created, checksum, data}` (checksum = SHA-256 от `data`) → записать в `backups/<время>_<тип>.json` → удалить копии сверх лимита 10.

**Восстановление:** найти копию (`latest` или имя) → прочитать → сверить SHA-256 → проверить структуру настроек → создать страховочную копию текущих настроек (`pre-restore`) → атомарно записать настройки.

### 3.5 Форматы данных
**Настройки (`config/settings.json`):**
```json
{ "register_name": "Касса №1", "currency": "RUB", "denominations": [10, 5, 2, 1] }
```
**Вход (`input.txt`):** см. FR-4.
**Выход (`output.txt`):** строки вида `Сдача 78: 10 x 7, 5 x 1, 2 x 1, 1 x 1 (всего 10)`.
