# Регламент технического обслуживания

Документ определяет порядок обслуживания программы «Coin Change» и её данных: кассовых настроек `config/settings.json` и резервных копий в папке `backups/`.

## 1. Ответственность

| Роль | Обязанности |
|---|---|
| Пользователь / оператор | Создание резервных копий, проверка копий, ведение журнала обслуживания. |
| Администратор / разработчик | Обновления, запуск тестов, аварийное восстановление. |

## 2. Перед началом работы
- Проверить версию Python: `python --version` (нужен 3.8 или новее; на Linux/macOS — `python3`).
- Убедиться, что `coin_change.py`, папки `config/` и `backups/` находятся в одной папке проекта.
- Проверить, что `config/settings.json` содержит корректные номиналы (`python coin_change.py backup` сообщит об ошибке, если файл повреждён), и что на диске есть место для копии.

## 3. Плановые работы

| Периодичность | Работа | Команда / действие |
|---|---|---|
| Перед каждым изменением номиналов | Создать резервную копию | `python coin_change.py backup` |
| Ежедневно (при работе с кассой) | Создать копию и убедиться, что она появилась | `python coin_change.py backup`, `python coin_change.py backups` |
| Еженедельно | Проверить целостность всех копий (все со статусом «OK») | `python coin_change.py backups` |
| Еженедельно | Проверить программу на контрольном примере (ожидается `10 x 7, 5 x 1, 2 x 1, 1 x 1`, всего 10) | `python coin_change.py change --amount 78` |
| Еженедельно | Скопировать папку `backups/` на внешний носитель или в облако | вручную |
| Ежемесячно | Проверить восстановление на тестовой копии проекта | `python coin_change.py restore` |
| Ежемесячно | Запустить автоматические тесты | `python -m unittest discover -s tests -v` |
| После обновления Python или программы | Запустить тесты и ручные тест-кейсы | см. `docs/TEST_CASES.md` |

## 4. Порядок изменения номиналов
1. Создать резервную копию (`backup`).
2. Изменить номиналы: `python coin_change.py set-coins 10 5 2 1` или пунктом меню 3.
3. Проверить расчёт на контрольном примере (`change --amount 78`).
4. Записать изменение в журнал (раздел 8).

## 5. Аварийное восстановление

| Сообщение / ситуация | Действия |
|---|---|
| `config/settings.json` удалён (расчёт идёт по номиналам по умолчанию 10, 5, 2, 1; `backup` сообщает «Файл настроек не найден») | `python coin_change.py restore` |
| `config/settings.json` повреждён («Файл настроек повреждён») | `python coin_change.py backups` → `python coin_change.py restore` |
| Нужна конкретная версия | `python coin_change.py restore <имя_файла>.json` (имя — из `backups`) |
| «Контрольная сумма SHA-256 не совпала», «Неверная структура копии», «Файл копии повреждён» | Копия повреждена, настройки не изменены. Выбрать другую копию со статусом OK (`backups`) или взять копию с внешнего носителя. |
| «Резервных копий нет» | Вернуть папку `backups/` с внешнего носителя; иначе задать номиналы заново: `set-coins 10 5 2 1`. |
| Восстановили не ту версию | В `backups` найти файл с пометкой `[страховочная]` (состояние до восстановления) и выполнить `restore <имя_файла>.json`. |
| «Невозможно выдать сумму … (остаток N)» | В номиналах нет монеты 1. Добавить её: `set-coins … 1`. |

## 6. Хранение и очистка
- Хранится не более 10 последних копий; более старые удаляются автоматически (копия, из которой идёт восстановление, не удаляется).
- Файлы копий вручную не редактировать и не переименовывать: нарушится контрольная сумма, и копия будет отклонена. Исключение — удаление ненужных копий целиком.
- Содержимое `backups/` и файлы `output.txt`, `result.txt` не публикуются в GitHub (настроено в `.gitignore`).
- Файлы `*.tmp` в папках проекта, `config/` и `backups/` (остаются только после аварийного прерывания записи) можно удалить.

## 7. Обновление программы
1. Создать резервную копию (`backup`).
2. Получить новую версию: `git pull`.
3. Запустить автоматические тесты и контрольный пример.
4. При ошибках вернуться на предыдущую версию (`git checkout <тег или коммит>`) и сообщить разработчику.

Изменения проекта и документации фиксируются в GitHub с понятным сообщением к коммиту (см. `docs/GIT.md`).
