## 1. Общие сведения

### 1.1 Наименование
Консольная программа «Coin Change» для расчёта сдачи минимальным количеством монет (жадный алгоритм) с резервным копированием и восстановлением кассовых настроек (номиналов монет).

### 1.2 Основание для разработки
Учебное задание: создание консольной программы на языке Python с возможным вводом и выводом данных через файл и через консоль для расчёта сдачи минимальным количеством монет. Разработка алгоритма резервного копирования и восстановления кассовых настроек, пользовательской документации (ТЗ, руководства пользователя на русском и английском языках, регламента технического обслуживания), тест-кейсов и проверка работоспособности ключевых модулей на соответствие ТЗ.

### 1.3 Термины
- **Номиналы** — набор целых положительных чисел (достоинства монет), по умолчанию `10, 5, 2, 1`.
- **Сдача** — целая неотрицательная сумма, которую нужно выдать монетами; равна «оплачено − цена».
- **Жадный алгоритм** — на каждом шаге берётся наибольший номинал, не превышающий остаток суммы.
- **Кассовые настройки** — файл `config/settings.json` с набором номиналов; именно он копируется и восстанавливается.
- **Резервная копия** — файл формата JSON с копией номиналов, датой создания и контрольной суммой SHA-256.
- **Страховочная копия** — копия типа `pre-restore`, которая автоматически создаётся перед восстановлением.

## 2. Цель и назначение
Автоматизировать расчёт сдачи минимальным количеством монет и обеспечить сохранность кассовых настроек: возможность создать копию номиналов и восстановить их при потере или повреждении файла.

## 3. Требования к программе

### 3.1 Функциональные требования

| № | Требование |
|---|---|
| FR-1 | Расчёт сдачи минимальным количеством монет жадным алгоритмом; вывод количества монет каждого номинала и общего количества. |
| FR-2 | Ввод данных через консоль: интерактивное меню и аргументы командной строки. |
| FR-3 | Ввод из текстового файла (UTF-8): каждая строка — одно число (сумма сдачи) или два числа через пробел (`оплачено цена`); пустые строки и строки, начинающиеся с `#`, пропускаются. |
| FR-4 | Вывод результата в консоль и в текстовый файл (`--output`; при вводе из файла по умолчанию `output.txt`). |
| FR-5 | Сумма сдачи, «оплачено» и «цена» — целые неотрицательные числа; «оплачено» не меньше «цены». |
| FR-6 | Номиналы — целые положительные числа; хранятся в `config/settings.json` (по умолчанию `10, 5, 2, 1`); изменяются командой `set-coins` или пунктом меню 3. |
| FR-7 | Если сдача равна 0, выводится «монеты не нужны»; если сумму нельзя выдать имеющимися номиналами (нет номинала 1), выводится ошибка с остатком. |
| FR-8 | Создание резервной копии `config/settings.json`; перед копированием содержимое проверяется, копия некорректных данных не создаётся. |
| FR-9 | Восстановление настроек из выбранной или последней резервной копии с проверкой контрольной суммы и структуры данных. |
| FR-10 | Перед восстановлением автоматически создаётся страховочная копия текущих настроек (если файл существует и корректен). |
| FR-11 | Хранится не более 10 последних резервных копий, более старые удаляются. |
| FR-12 | При любой ошибке исходные данные не изменяются, а пользователь получает понятное сообщение. При обработке файла ошибочная строка не останавливает обработку остальных. |

### 3.3 Алгоритм расчёта

1. Проверить, что сумма — целое число ≥ 0 (для пары «оплачено цена»: оба числа ≥ 0 и оплачено ≥ цены, сдача = оплачено − цена).
2. Номиналы отсортировать по убыванию. Для каждого номинала `c`: `count, rest = divmod(rest, c)`; если `count > 0`, записать пару (`c`, `count`).
3. Если после перебора `rest > 0`, сумма не может быть выдана — ошибка.
4. Общее количество монет — сумма всех `count`.

Пример: номиналы `10 5 2 1`, сдача 78 → `10 x 7, 5 x 1, 2 x 1, 1 x 1`, всего 10 монет.

**Ограничение.** Жадный алгоритм оптимален для «канонических» наборов номиналов (например, 1, 2, 5, 10). Для произвольных наборов результат может быть неоптимальным: при номиналах `4, 3, 1` и сумме 6 программа выдаст `4 + 1 + 1` (3 монеты), хотя оптимально `3 + 3` (2 монеты).

### 3.4 Алгоритм резервного копирования и восстановления

**Копирование:**

1. Прочитать `config/settings.json` и проверить содержимое (FR-6). Ошибка — копия не создаётся.
2. Сформировать JSON `{created, checksum, data: {coins}}`, где `checksum` — SHA-256 от `data` (каноническая запись JSON: ключи отсортированы, без пробелов).
3. Атомарно записать в `backups/<дата_время>_<тип>.json` (тип `manual` или `pre-restore`).
4. Удалить копии сверх лимита 10 (самые старые). Копия, из которой идёт восстановление, при этом не удаляется.

**Восстановление:**

1. Найти копию: указанную по имени либо самую свежую обычную (`manual`). Копий нет или имя неверное — ошибка.
2. Прочитать JSON, сверить SHA-256, проверить структуру и номиналы. При ошибке настройки не изменяются.
3. Если `config/settings.json` существует и корректен, сохранить его как `pre-restore`.
4. Атомарно записать номиналы в `config/settings.json`.

Страховочную копию можно использовать для отмены восстановления: `restore <имя_страховочной_копии>`.

### 3.5 Форматы данных

**`config/settings.json`:**

```json
{
  "coins": [10, 5, 2, 1]
}
```

Если файла нет, при расчёте используются номиналы по умолчанию `10, 5, 2, 1`.

**Входной файл:**

```
# комментарий
78
100 22
```

**Результат (консоль и файл):**

```
Сдача 78: 10 x 7, 5 x 1, 2 x 1, 1 x 1 (всего 10)
Оплачено 100, цена 22. Сдача 78: 10 x 7, 5 x 1, 2 x 1, 1 x 1 (всего 10)
ОШИБКА (строка 3): Сумма не является целым числом: «abc»
```

**Резервная копия:**

```json
{ "created": "2026-10-23T12:00:00", "checksum": "<sha256>", "data": { "coins": [10, 5, 2, 1] } }
```

### 3.6 Интерфейс

Без аргументов запускается меню (пункты 1–5 и 0, см. `README.md`). Команды:

| Команда | Назначение |
|---|---|
| `change --amount N` | сдача для суммы N |
| `change --paid P --price C` | сдача для пары «оплачено / цена» |
| `change --input ФАЙЛ [--output ФАЙЛ]` | расчёт из файла; результат в `output.txt` или в указанный файл |
| `set-coins N [N …]` | задать номиналы |
| `backup` | создать резервную копию настроек |
| `backups` | список копий с проверкой целостности |
| `restore [ИМЯ]` | восстановить настройки из копии |

Если сумма не указана, программа запросит «оплачено» и «цену» в консоли.

**Коды возврата:** 0 — успех; 1 — ошибка данных, файла или копии; 2 — неверные аргументы командной строки либо ошибочные строки во входном файле (остальные строки обработаны).
